# 전수 점검 기록 — 2026-08

> [omarchy-setup](../README.ko.md) 참고 문서. 스크립트가 아니라 **저장소 전체를 훑은 점검의
> 기록**이다. 발견 당시의 상태를 남기며, "수정됨" 표시는 이 점검과 같은 브랜치에서 고친 것이다.

점검 시점: 2026-08-20. 대상: 코드 전부(셸 3.8k줄 + QML/Lua/JS)와 문서 전부(2.2k줄).
전 셸 파일 `bash -n` 통과. 판정 로직(TriggerKeys awk, 패키지 가드 분류, 로더 블록 왕복)은
샌드박스에서 실제로 돌려 확인했다.

## 점검 축

파일 단위가 아니라 여섯 축으로 봤다. 이 저장소의 버그는 파일 안보다 **파일 사이의 약속**에
숨기 때문이다.

1. **문서 ↔ 코드 일치** — 문서가 하는 사실 주장을 전부 뽑아 코드와 대조
2. **스크립트 간 불변식** — 실행 순서, 공유 폴더(`.installed`), 로더 블록, `zz-` 로드 순서
3. **멱등성과 왕복** — install→install, install→remove→install 의 잔여물
4. **실패/경계 경로** — tty·gum·omarchy·네트워크·hyprctl 없음, Hyprland <0.55, sudo 실패
5. **bash 견고성** — 인용, `set -e` 함정, /dev/tty, 마커 sed
6. **QML/Lua** — null 가드, 바인딩 루프, 닫기 4중 방어

## 발견 — 1차 수정 (버그 3건)

### 1. `setup-korean.sh remove` 가 Hyprland reload 를 건너뛰었다 (중간)

`run_remove` 가 `hyprland.lua` 의 require 블록을 지우고도 `HYPR_CHANGED` 를 세우지 않아,
마지막 `reload_hyprland` 가 "변경 없음 — reload 불필요" 를 찍고 아무것도 안 했다.
**증상**: remove 후에도 우측 Alt 한/영과 래핑된 SUPER+SPACE 가 재로그인 전까지 세션에
그대로 남고, 로그는 변경이 없었다고 말한다.
**수정**: 블록을 지운 분기에서 `HYPR_CHANGED=1`. 샌드박스 HOME 으로 remove 를 돌려
reload 가 뜨는 것과, 두 번째 remove 에서는 다시 안 뜨는 것(멱등)을 확인했다.

### 2. 한글 스텝은 패키지 설치 실패가 전체 실패였다 (중간)

`set -e` 아래의 `omarchy pkg add` / `sudo pacman -S` 가 실패하면(비번 거부, 네트워크 없음)
1단계에서 즉사해 2~9단계(환경변수·프로필·트리거키·바인딩)가 전부 안 돌았다.
[install.md](install.md)의 "그때도 설정 파일 설치는 진행되므로" 는 bash-config 에만 참이었다.
**수정**: bash-config 와 같은 방식으로 `|| warn ... 계속 진행`. 이제 문서 주장이
네 스텝 모두에 참이다.

### 3. 다른 섹션의 `Control+space` 가 영구 재패치 루프를 만들었다 (낮음)

`fcitx_triggerkeys_clean` 의 Control+space 검사가 **파일 전체**를 봤는데, 패치하는 awk 는
`[Hotkey/TriggerKeys]` 섹션만 고친다. 다른 핫키 섹션에 `0=Control+space` 가 있으면 clean 이
영원히 거짓 → 매 실행이 백업을 만들고 fcitx5 를 재시작했다 — "변경 없으면 재시작 안 함"
(Enter 무한 반복 방지) 설계를 무력화하는 조합.
**수정**: 검사도 TriggerKeys 섹션으로 스코프. 세 케이스(다른 섹션에만 있음 / 진짜 더러움 /
깨끗함)로 재현·확인했다.

## 발견 — 2차 수정 (낮음·사소 일괄)

전부 샌드박스에서 수정 전 재현 → 수정 후 통과를 확인했다.

| 발견 | 수정 |
|---|---|
| **install→remove 왕복이 원본 끝의 빈 줄을 먹었다** — "파일 끝의 빈 줄 전부 삭제" 방식이 원인. 네 곳(bash 로더, korean·workspaces·sudo-pop 의 hyprland.lua 블록)이 같은 패턴이었다 | 마커 블록 + **블록 앞에 설치가 넣은 빈 줄 하나만** 지우는 awk 로 네 곳 모두 교체. cat 덮어쓰기로 파일 권한/inode 유지. 끝에 빈 줄 있는 원본으로 왕복 byte-identical 확인 |
| **workspaces `revert`/`remove` 가 셸이 죽어 있으면 파일 정리조차 못 했다** — `require_shell` 이 맨 앞에서 die | 바인딩 제거를 셸 확인 앞으로. "레이아웃에 없음" 은 shell.json 파일로 직접 판정해 **셸 없이도 끝난다.** 레이아웃이 아직 플러그인을 가리키면 여전히 멈춘다 — 레이아웃이 가리키는 파일을 지우면 바가 깨지므로, 그건 보호 동작이다 |
| **hyprctl 없는 머신에서 `revert` 가 조용히 죽었다** (위 항목 테스트 중 발견한 기존 잠복 버그) — `remove_binding_line` 의 마지막 줄 `command -v hyprctl && hyprctl reload` 가 함수 반환값 1 → `set -e` 즉사 | 명시적 `return 0` 추가. fakebin PATH(omarchy-shell·hyprctl 없음)로 revert 정상 완료 확인 |
| **`source ... install` 후 `msb_status` 가 호출자 셸에 남았다** | 위치 인자로 옮기고 unset. 소싱 후 `declare -p` 로 미존재 확인 |
| **체크리스트와 `status` 의 판정 불일치** — 저장소에서 지운 파일이 설치본에 (우리 소유로) 남으면 메뉴는 `latest`, status 는 `in sync: no` | `install.sh` 의 bash-config 판정이 `.installed` 목록도 대조. 유령 항목 넣고 `--list` 로 outdated 전환 확인 |
| **XDG autostart 억제 파일을 백업 없이 덮어썼다** — 사용자가 만든 파일일 수 있다 | 내용이 다를 때만 쓰는 자리이므로, 쓰기 직전 `backup` 추가. 래퍼는 항상 우리 파일이라 그대로 |
| **패키지 가드의 제안 실행이 glob 확장 대상** — `pacman -S 'foo*'` 의 제안 `omarchy pkg add foo*` 가 `cmd=($suggested)` 에서 cwd 파일명으로 확장 | `read -ra` 로 분리 (단어 분리만, glob 없음). foo1·foo2 있는 폴더에서 `foo*` 보존 확인 |
| **`omarchy_default_bind_cmd` 의 sed 가 매치 실패에 줄 전체를 반환** — 향후 Omarchy 가 바인딩에 옵션 테이블을 붙이면 깨진 Lua 가 생성될 수 있었다 (점검 당시 "추정" 분류) | `sed -nE ... p` 로 매치될 때만 출력, 빈 값이면 다음 파일 계속. 매치/비매치 형식으로 확인 |
| `install.sh` 의 `VERB`·`PRESELECT` 죽은 변수 | 삭제 |
| `curl \| bash -s -- --help` 에서 usage 의 awk 가 `$0`(= "bash") 을 파일로 열려다 실패 | 스크립트 파일이 없으면 한 줄 요약 출력. 파이프 실행으로 확인 |
| 헤더 오타 "question advance" | "question **in** advance" |

## 문서 ↔ 코드 대조

**문서에 있는데 코드와 달랐던 것** (1·2번은 수정으로 해소)

1. ~~"패키지 실패해도 설정 파일 설치는 진행"~~ — 한글 스텝은 거짓이었다 → 1차 수정
2. ~~"왕복 후 ~/.bashrc 바이트 동일"~~ — 원본 끝 빈 줄이 있으면 거짓이었다 → 2차 수정
3. [bash-config.md](bash-config.md)의 로더 블록은 `"$HOME/..."` 표기지만 실제 설치본에는
   절대경로가 박힌다 (heredoc 이 확장한다). 동작 무해, 표기만 불일치
4. [install.md](install.md) 상태표의 `zz-pkg-guards` 행 — install.sh 에 별도 스텝이 없다
   (bash-config 판정 안에 흡수). 본문("체크리스트에 없다")과 표가 서로 다른 얘기를 한다

**코드에 있는데 문서에 없는 것**

1. `setup-korean.sh` 의 `LEGACY_INPUT_LUA` / `LEGACY_BIND_LUA` 환경변수 (지원 변수 목록에 빠짐)
2. 액션 별칭들 — bash-config 의 `setup|apply|sync`, workspaces 의 `use|apply|sync` /
   `restore|off`, sudo-pop 의 `update|upgrade`
3. `install.sh --dir` 은 저장소 안에서 실행하면 무시된다

## 의심했다가 통과한 것

점검 중 의심했지만 실측/대조로 문제없음이 확인된 것들. 다음 점검이 같은 길을 다시 걷지 않게 남긴다.

- `fzf --raw` / `result:best` — 설치본 fzf 0.74.2 에 실존 (man 확인)
- 패키지 가드 분류 15케이스 매트릭스 — 문서 표와 전부 일치 (`-Ss` 통과, `-Sy`/`-Fy` 질문,
  `-U` 확인만, `--needed` 단독은 질문, `sudo -u/-E/--` 파싱 정상)
- TriggerKeys awk 재작성 — 값 보존, Control+space 제거, Hangul 보장, 인덱스 재정렬 정상
- 제거 역순 체인 — 위젯 → sudo-pop(`--uninit` 이 bash 로더 생존 중에) → bash → 한글 →
  빈 `~/.config/minsoft1115` 정리까지 정합
- gum 라벨 콤마 없음, 상태 칸 ASCII 22자 정렬 정확
- `set -e` 아래의 `[ ... ] && ...` 패턴들 — 함수의 마지막 명령이었던 workspaces 의
  hyprctl reload 한 곳(2차에서 수정)을 빼면 전부 조건 문맥이거나 비최종 명령이라 안전
- PeekCard 의 숨긴 Column 측정 — 설계 문서의 실측 기록으로 갈음
